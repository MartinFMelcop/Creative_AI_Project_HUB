# Strict dialogue conditions in an actual owned service

This method inspects selected condition-expression contracts from the preserved XP
source and adapts a bounded strict condition compiler into the existing original C#
service. It does not run historical Ruby, import dialogue fiction or model NPC psychology.
The service's actual private owner still pays costs and supplies goods; a condition or
selected text is not work, consent, an acquired component or completed travel.

## Source evidence and selected boundary

`assay.py` reads the actual preserved DEV/DIST runtime and variant tables. Both runtime
copies are byte-identical; both table copies are byte-identical. Each table has29rows,
26columns and23distinct ConditionsExpr strings, including blank unconditional variants.
Rows combine scalar comparisons with HasTag/HasFlag queries; one actual expression has
parenthesized conjunction/disjunction. Runtime-declared HasRecentEvent queries and their
suffix/scoped binding are separate from these29actual variant expressions.

The selected reusable contract is deterministic comparisons, conjunction/disjunction and
parentheses. Destination types, allowed symbols, full-input consumption, empty/missing
values and boolean/query bindings require explicit policies. Source relation-before-state
lookup, key_0_100 fallback, numeric-looking string coercion and single-equals alias are
not silently called equivalent to typed destination behavior.

Exact source branches motivate the narrow rejection of direct permissive parsing as a
complete **private paid-service permission authority**: tokenizer skips unknown
characters, `Parser.parse` does not check trailing tokens, closing-parenthesis consumption
is unchecked, a missing primary can become true, and exceptions recover through a
different split-based fallback. Empty unconditional dialogue can be legitimate in its
original selection context; this does not reject that case or the whole source library.
These are static observations, not demonstrated historical exploits or Ruby execution.

The assay retains source identities, row IDs/expressions and exact source section line
ranges/hashes. Its declared malformed inputs are prospective destination negatives,
not claimed Ruby outcomes. Actual destination execution and consumer controls live in
the separately recorded current execution evidence.

## Reproduce source inspection

From the maintained workspace, with Python3.11+:

```bash
python3 labs/world-gameplay/dialogue-conditions/assay.py --output /tmp/dialogue-condition-source-new.json
```

Output must be a new external file. The assay never executes or modifies protected
reference scripts. It checks identities before/after inspection and refuses drift.
Static source agreement is separate from the actual C# compiler and browser execution.
Do not sum repeated expressions, native/browser assertions or negative controls into
participants, independent studies or measured effort.

variant rows, producing fully known source-shaped cases for actual C# comparison.
