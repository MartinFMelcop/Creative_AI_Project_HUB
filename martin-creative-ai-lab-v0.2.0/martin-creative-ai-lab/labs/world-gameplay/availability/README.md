# Phase masks and authoritative availability

This selected method reads the preserved Rave Master snapshot
`36af1651271422ae33856e8b5d7b45702215f165` without executing its scripts or importing
its fiction. The question is whether literal advertised phase eligibility can be
preserved while actual NPC activity owns availability and only accepted work owns
completion. A phase mask is not observed physical presence, consent, a finished job,
a return receipt or a complete NPC scheduler.

## Sources and narrow extraction

[run.py](run.py) records exact hashes and sizes for the actual DEV schedule table,
CORE and bundled time-phase tables, DEV/bundled NPC state and DEV dialogue helper.
The schedule CSV contains27 NPC rows. The five CORE phase orders are0–4. The
[source cases](source-cases.json) contain all **135 NPC×phase cases**, with booleans
constructed directly from exact mask membership before C# execution. No names,
location strings, map keys or fiction are copied into the original consumer.

The parser rejects changed ordered headers, wrong row widths, duplicate/unknown IDs,
empty/duplicate/unknown mask phases and missing/reordered time phases. It does not
interpret `LocalPreferido` as code or silently infer absent map coordinates.

Material unresolved conflicts are retained in the output:

- NPC-0006 advertises phase1 while its preferred-location description says home then.
- Worker masks include phase1 while the global phase table says `DESCANSANDO`.
- Worker dawn masks/global work permit phase4 while repeated heuristic notes say
  off the street in phases2–4.
- Unique NPCs and initial-scene notes allow quest/cutscene control; the table supplies
  no complete override-priority or observation implementation.

Consequently observed source position remains **UNKNOWN**. The protocol's boolean
means only literal phase-mask eligibility. Whole NPC schedules, dialogue scoring,
reputation, position conflicts, quest/world catalogs and historical Ruby/RMXP execution
remain unresolved. Hashes bind inspected inputs; they do not prove those systems run.
