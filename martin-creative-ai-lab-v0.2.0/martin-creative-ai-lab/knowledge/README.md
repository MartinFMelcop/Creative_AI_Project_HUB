# Derived knowledge

This directory preserves contextual lessons from executed work in the historical
origins, applied-research laboratories and Virgo Diamond development. It is a
retrieval layer for observations, interpretations and decisions, not a fourth
brain or a copy of the [three durable knowledge volumes](../brains/README.md).
Storing files in Git does not train a model or establish that an agent read them.

Read the relevant lesson and its linked execution record before reusing a result.
The record's inputs, source identities, environment and limits bound the claim;
an old passing run does not establish current behavior. Preserve negative and
inconclusive findings alongside successful corrections. New execution evidence
may revise a derived lesson; ordinary work must not rewrite the brain sources.

## Record only what changes a decision

Use the smallest entry that lets a reader recover:

- **Question and context:** what problem, source/version and conditions matter.
- **Source or experiment:** links to inspectable inputs, code and execution evidence.
- **Observation and outcome:** what was measured; label positive, negative or
  inconclusive relative to the tested claim.
- **Interpretation or decision:** what follows, separated from what was observed.
- **Validity and practical consequence:** limits, actual consumers, candidate
  reuse and the condition that would require revisiting the lesson.

A proposed technical transfer belongs in [transfers.json](../registry/transfers.json)
when an explicit destination is useful. A validated transfer needs a real
destination consumer and its execution evidence; a reusable explanation alone
does not create shared code or integrate a capability into Virgo Diamond.
