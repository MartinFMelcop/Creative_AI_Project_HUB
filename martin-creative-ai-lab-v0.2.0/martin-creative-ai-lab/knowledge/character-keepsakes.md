# Character keepsakes — preserve choice without competing with action feedback

**Question/context:** Can an existing crossing's completed action leave an optional
visible trace across local reentry without granting power or obscuring play feedback?
Baseline `ca432cc395e7dfebf989d8077f0280baff2dd1ca` displayed a temporary result token;
its next crossing/new process retained no owned or worn expression.

**Sources:** [Actual consumer](../north-star/prototype/README.md),
[execution and controls](../evidence/north-star-keepsakes/RUN.json), ENG-010 failure
containment, SCI-017 positive/negative controls, CRE-001 direct author identity direction
and CRE-004/030/062 hypotheses about owned rewards, memories and cosmetic expression.
These creative hypotheses are not validated player preferences or canon.

**Observation:** Both full normal approach policies complete and earn their respective
mark; rehearsal, defeat, abandonment and a terminal fixture without a signature response
do not. Explicit wear and put-away survive four separate engine invocations per source/
PCK. Worn and unworn complete Combat snapshots match exactly. Invalid primary bytes
remain unchanged, pending session earning survives ordinary write/replace failure and
retry retains previously loaded as well as newly earned marks. Same-directory validated
replacement avoids deleting the prior complete file before a successful rename.

**Negative finding/refinement:** The first pending-save footer displaced live action
feedback throughout later crossings. A separate agent found this real priority conflict;
new controls now require the live rejection reason while the header indicates pending
save and pause/result expose recovery. The facing line also crossed the new body mark;
render inspection moved the direction cue outside the body. Neither fix changes geometry.

**Interpretation:** A small local appearance record can connect an executed act to player
choice without introducing stats, repeated acquisition incentives or account infrastructure.
Save diagnostics belong where actionable and must not replace immediate threat/action
information. Recovery must retain all known marks, not merely awards earned after failure.

**Validity limit:** Fixed automated policies, synthetic OS keys and agent image review;
no independent human recognition, enjoyment, accessibility or learning validation. Editable
JSON has no server authority, concurrency protection or demonstrated power-loss durability.
No named character/account identity, session restore or MMORPG progression is implemented.
Pending changes are lost if the application closes before a successful retry.

**Practical consequence:** Keep explicit reversible expression separate from combat state;
test both failure messaging and later live play when adding persistence. Judge whether
players notice/value these marks through actual observation before enlarging collections.


## A visible fitting must expose its functional price

**Question/context:** can preparation add a reversible character build choice without
turning cosmetic keepsakes into power? **Source:** [workshop execution](../evidence/north-star-workshop/RUN.json),
CRE-022/023 hypotheses, ENG-005 and SCI-017. **Observation:** one native timed make
spends a single blank; undo refunds it only before deployment. The coat/wrap changes
actual health, walk/guard/step motion and remains visible in the same consumer.
All standard-equipment mechanical observations equal the prior verified consumer.

**Refinement:** held interaction initially replaced success with a duplicate-action
message; release-to-rearm preserves confirmation. Image inspection separated station
range geometry from comparison text. **Interpretation/consequence:** show the functional
price beside the make action and keep cosmetic memory separate from fitting stats.
**Validity:** fixed routes and synthetic OS input, not perceived identity, general
balance, profession demand or human preference. One session blank and reversible undo
are not an economy, inventory or persistent progression system.

## An accepted preview action can still be visually missing

**Question/context:** can a free appearance workflow show the same character and paid
actions as the real consumer? Baseline `e7c7563`; [execution](../evidence/north-star-character-look/RUN.json).
**Observation:** initial controls passed paid-action assertions, while the actual
editor showed Blade/idle. Replacing the preview model after stepping attached its
observer after the first event. Attaching before stepping and observing natural loop
reset restores blade/draw gestures. Review also moved enlarged art clear of its legend.

**Interpretation/consequence:** inspect the observer's actual output, not just the
underlying accepted action. Preparation, first discrete event and observer attachment
order belong to the preview contract. Keep visual expression separate from combat
and test both real rendering and unchanged full journeys. **Validity:** fixed/native
samples and agent inspection, not perceived identity, taste or independent accessibility.
CRE-009/029/066 motivate expression; ENG-023 and SCI-014 limit what passing controls prove.


## Independent cosmetic choices need independent recovery intent

**Question/context:** does explicit free appearance survive real process reentry
without changing legacy mark ownership or restoring play? Baseline `05454410` resets
an applied look. **Sources:** ENG-010, CRE-030 H, SCI-017 and
[actual migration/restart execution](../evidence/north-star-appearance-continuity/RUN.json).

**Observation:** legacy load/cancel preserves bytes; explicit apply alone creates v2.
52 controls and 20 actual source/PCK restart processes retain applied choices across
both goals and earned marks. Unknown primary bytes remain untouched. Repair keeps
pending applied look, restored worn selection and unsaved draft distinct. Prior PCK
rejects v2 safely. JSON whole numbers arrive as floats; strict validation followed
by normalization is required. Capture mtime alone did not establish complete JSON.

**Interpretation/consequence:** track intent per independent field, rather than let
one cosmetic edit overwrite another during recovery. Preserve old formats until an
explicit new choice requires migration. Bound capture-completion polling without
replaying inputs; instrument races are not product failures. **Validity:** editable
single-device cosmetics, fixed native/synthetic controls and agent inspection; no
account, persistent RPG power, power-loss/concurrency guarantee, human recognition
or preference evidence. Pending unsaved changes can still be lost on close.
