## Active initiative — distinctive character agency through connected adventures

**Objective/consumers/value:** Make North Star's identity direction tangible in its
actual local playable consumer and create evidence for future production architecture.
Players should express different approaches and consequences through a connected
adventure; this remains a prototype frontier within the larger original MMORPG vision.

**Implemented and verified baseline:** The connected local adventure retains equipment
trade-offs, appearance/local cosmetic memory, courier aid, escort and return goals.

commit 1.5 seconds at a grounding lever and sacrifice one winch integrity to silence the
ward. Damage can interrupt; two catches and actual living exit remain mandatory. Retry
restores the prepared arrival without stacking aid. [Current execution](../evidence/north-star-return-feedback/RUN.json)
binds controls, eight two-goal approach/outfit journeys, source/PCK/Linux release,
matched prior-delivery observations, native keyboard interaction and inspected images.
Equipment authorship remains bounded by [the catalog contract](../north-star/prototype/data/README.md);
[its original execution](../evidence/north-star-fittings/RUN.json) remains historical evidence.
Detailed mechanics belong in [the prototype guide](../north-star/prototype/README.md).
Capability states and local-prototype maturity remain unchanged; no new lab/origin transfer.

**Latest product improvement:** The courier offer previews actual prepared resources,
grounding cost and the different consequence of taking a winch hit first. Return play
now retains a causal last-attempt review: elapsed work, interruption cause and zero/paid
cost, with remaining options or retry. These observations use actual model transitions;
no automatic aid/strategy selection or balance change. Shared preparation logic keeps
the preview and actual return consistent. [Current execution](../evidence/north-star-return-feedback/RUN.json)
binds source/PCK/Linux controls, complete journeys, native input and inspected images.

**Consumed production instrument:** The [return evaluator](../north-star/prototype/analysis/README.md)

## Active initiative — server-owned shared-world foundations

**Objective/consumer:** Resolve the missing client/server trust boundary using the
existing actual escort model, before committing to a production engine or shared-world
implementation. The [developer authority consumer](../north-star/prototype/authority/README.md)
now separates a real TCP loopback server and remote consumers. An interactive developer
window accepts keyboard/mouse events and presents interpolated confirmed positions;
resources, threats and terminal results remain server-owned. Focus loss suspends inputs,
not the world, and missed releases recover without synthesizing presses. Server physics
owns time, catalog resources and paid actions; clients submit bounded sequenced intents.
Silence/disconnect neutralize actions without pausing or resetting the model. Intent
heartbeat is now bounded by monotonic time, independent of new snapshots; stale windows
send only neutral while controls remain suspended. Arrival gap is not server-state age.

**Verified scope:** [Current execution](../evidence/north-star-preparation/RUN.json) binds
server authority with read-only action advice and native intent/transport/visual controls, complete interactive
source/PCK journeys and actual OS input/focus recovery. [Unchanged interaction/visual
evidence](../evidence/north-star-action-feedback/RUN.json) retains inspected world/terminal images.
The [original authority execution](../evidence/north-star-authority/RUN.json) remains
historical. Existing playable source, PCK, release and
capability evidence remain unchanged. No new lab, capability state or MMO maturity claim.

**Latest interaction improvement:** The remote preparation screen now inspects the
actual server-loaded catalog before starting a character. It compares clothing health,
movement and unguarded recovery, combines that choice with the existing approach/
technique, and explicitly commits once. Confirmed resources must match the selected
tuple; inspection cannot start or spend the model, and entry cannot be reopened.
Twelve offered tuples per source/PCK delivery execute their real paid step and distinct
held-guard consequence. Action cards still expose costs/restrictions during play.
No new ability, final class, balance, human comprehension or shipped-network claim.

**Verification reliability:** The [startup correction](../evidence/north-star-window-startup/RUN.json)
resolved the bounded verifier startup dependency; its full six-job CI passed before this execution. Window startup now precedes authority startup: a reserved port and
actual rendered/input acknowledgement separate renderer latency from the unchanged
nine-second test server lifetime. Normal and deliberately delayed source/PCK OS checks
retain every input/cost/focus/disconnect requirement. Missing/stopped windows remain
bounded failures with retained diagnostics. This improves the executable verifier;
it is not new player functionality or evidence of the exact prior CI failure cause.

**Consumed research instrument:** The [transport study](../north-star/prototype/authority/TRANSPORT.md)
now runs the actual fixed-input consumer through direct/transparent controls, bidirectional
retention and downstream batching. [Execution](../evidence/north-star-transport/RUN.json)
retains all 16 source takes, two PCK integration takes, and an exploratory pilot with
its own identities. Controls win; delayed/grouped outcomes expose policy and input-lease
limits without changing costs. A current targeted rerun retains eight source/two PCK

takes. An initial overlapping-suite source take fails with two clears; the serial repeat

isolated scheduling-cause claim. These takes do not establish human thresholds or balance.

**Missing/dependencies:** A shipped network player, prediction/reconciliation, multiple
players, authentication, encrypted remote transport, persistence and reconnect
are absent. Loopback fixed policies establish neither player experience nor latency or
capacity. Pinned Godot 4.6.3 is the executable experiment, not a production engine decision.

**Next/continuation:** Compare deliberate adoption/integration of the new source-only
rush behavior and independent player comprehension against freshness feedback, policy adaptation and demonstrated
prediction/reconciliation needs. Independent neutral heartbeat closes the cadence

Interactive input is now demonstrated; a larger network stack is not automatically valuable.
