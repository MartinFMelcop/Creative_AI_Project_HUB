# The gauge that stays

An original finite C# consumer of exact item identity and required, nonconsumed tools.
The bench spends materials to make a rig, retains its gauge, then spends the actual rig
on an actual Crossing entry. A recipe is not an owned tool; an output is not an entered
encounter; winning the survey is not final expedition completion.

This is **ONE legacy/laboratory item-tool unit**. The original consumer, interface and
CI support the same source-consumption beneficiary, not additional North Star or
portfolio units. Original supplies, names and fixed preparation are experimental setup
under Martin's direction, not approved canon or imported historical item/quest fiction.
The existing authored request/journal, other owners and current downloadable scene remain
unchanged; this source entry creates no new packaged release line.

## Execute the actual consumer

Use the existing pinned SDK 10.0.401. From the maintained workspace:

```sh
cd north-star/csharp
dotnet build ../tooling-study/Host/NorthStar.ToolingStudy.csproj -c Release -m:1 --disable-build-servers
dotnet ../tooling-study/Host/bin/Release/net10.0/NorthStar.ToolingStudy.dll --serve 8766 ../tooling-study/web --seconds 300
```

Open the printed loopback URL. Ports are bounded to 1024..65535 and host lifetime to
1..600 seconds. Ctrl+C stops the process. This source-built demonstration needs the SDK
and a graphical browser; it is not another SDK-free downloadable artifact.

The equipped trial starts with **four fiber, two binder and one owned gauge**. These
are explicit assay supplies, not evidence of acquisition or a free-world tool grant.

| Action | Actual consequence |
|---|---|
| Craft | Requires the gauge. Spends two fiber and one binder; produces one Trail rig; retains the gauge. |
| Enter | Requires one actual Trail rig. Consumes it once and starts the real fixed Lure/Trail Crossing. |
| Walk, Dash, Lure, Wait | Executes the real active encounter action; its announced threat owns contact and outcomes. |
| Fresh equipped trial | Explicitly replaces the ephemeral study with the equipped initial setup. |
| Fresh missing-gauge trial | Explicitly replaces it with the same materials and zero gauges; production must refuse without spending them. |

Two crafts can spend all four fiber and two binder while retaining the same one gauge.
Two actual entries then consume the two actual outputs. Crafting cannot take place during
an active or completed expedition. A survey win still requires an explicit next entry;
reading, redraw and elapsed wall time never start it. Failure consumes its entry rig
without refund and can leave the final journey unfunded. The gauge cannot finance a
missing rig or be consumed as material.

The page exposes actual inventory, transactions, entries, next threat and encounter
state. Refusals remain inspectable. Focus loss or an uncertain response makes the view
stale until an explicit read; no request is automatically retried. Accepted fresh-trial
commands invalidate older queued intentions. Fresh presets replace this local trial,
not a world transaction, recovery of spent supplies or an acquired tool. Stopping or
expiry loses the session; no saved campaign or account is established.

## Reuse and the selected source contract

[Tooling.cs](Rules/Tooling.cs) is a C#8/netstandard2.1 adapter referring to the unchanged
[Domain inventory](../csharp/Domain/Crafting.cs). One private existing CraftInventory
still owns quantities, atomic transactions and committed request identities. The
adapter adds exact known-item identities and immutable retained-tool requirements
without rewriting the transaction owner. A consumable used as an ingredient retains
its one identity; a separate material alias is not invented.

The selected destination policy forbids any declared retained tool as an input in any
recipe and through `Consume(tool)`. This is explicit scope, not a recovered rule for
all possible historical tool/ingredient overlap. Tool ownership is required before
production. Missing requirements, invalid identities and refused transactions cannot
spend materials. Accepted retries preserve the existing ledger behavior.

The actual [Host](Host/Room.cs) refers to both the new adapter and the real unchanged
Crossing. Fixed Lure/Trail is scene setup, not free approach selection. The library's
portable target does not make the .NET10 host, file/process APIs or actual Crossing
executable Unity/netstandard compatible. No Unity Editor/import or Windows/Steam
execution follows from a successful Linux build.

The preserved Rave Master snapshot `36af1651271422ae33856e8b5d7b45702215f165` supplies
historical data, particularly `ITEM_CLASS_RULES.csv` R7/R8, `ITENS_MASTER.csv` and
`CRAFTING_RECIPE.csv`. [The laboratory method](../../labs/economy-simulation/tooling/run.py)
binds exact source paths and variants. R7 separates required nonconsumed tools from
ingredients; R8 keeps a consumable's identity when it also appears as an ingredient.
Historical instructions and CANON labels remain source data, not North Star authority.

## Identity is not authorization or effects

The method preserves all 372 literal source item identities as observations, while only
370 structurally valid records enter exact lookup. Two 47-field torch/lantern records
against a 48-field header remain quarantined; original bytes are not repaired. All 81
literal output/ingredient/tool references in 21 source recipes resolve to those known
identities. This is identity evidence, not historical recipe execution.

The assay also retains consequential limits:

- Four recipes have multiple unlock references without resolved AND/OR meaning.
- Two recipe references point to a quest marked for disregard/rewrite; the reference
  cannot grant completion or an unlock.
- The 78 skill-unlock records retain conflicting or missing recipe skill namespaces.
  Numeric IDs are not silently translated between them.
- The source tool's `StackMax=1.0` identifies a parseable bound; its missing Backlog price
  is not zero cost or proof that the player owns it.
- Header-only alias and duplicate-QA files do not supply aliases or a successful audit.
- Item identity, source implementation status and notes do not supply consumable effects,
  item prices, quest completion, profession policy or current author approval.

The normalized identity data grants no inventory, price, source recipe activation,
unlock, effect or fictional world. Full item/tool/unlock catalogs and source runtime
integration remain unresolved beyond the narrow recorded contracts.

## Creative and production boundaries

CRE-005(A) informs visible action/cost consequences. CRE-022/023(H) distinguish useful
work and a few consequential steps from repetitive production or XP; CRE-071(H)
discourages a catalogue without demonstrated use. These influences do not approve
specific rigs, profession balance, source quests or final creative canon. Here, actual
output consumption in an encounter supplies the beneficiary beyond an inventory panel.

Actual licensed Unity/Windows delivery and appropriate author/player/device assessment
remain stronger acceptances for production and experience when access exists. No agent,
source hash or browser assertion establishes comprehension, accessibility, enjoyment,
balance, commercial clearance or human quality. Build/Operations remains incomplete.
Unique prior sources, saves, media, rights-bearing materials and notices retain their
own consumers and preservation obligations; none is retired by this study.
