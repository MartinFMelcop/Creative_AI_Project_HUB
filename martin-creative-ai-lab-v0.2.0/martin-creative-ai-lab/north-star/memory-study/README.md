# The fitting window

An original finite C# service makes actual past work, current local support and a
recent named demonstration distinct. Help observed at West does not authorize East.
An expired opportunity does not erase the work or an acquired fitting. The two static
original vector benches observe those actual states rather than supply them.

## Run

Use SDK10.0.401 from the maintained workspace:

```bash
dotnet build north-star/memory-study/Host/NorthStar.MemoryStudy.csproj -c Release
dotnet north-star/memory-study/Host/bin/Release/net10.0/NorthStar.MemoryStudy.dll --serve 8099 north-star/memory-study/web --seconds 600
```

Open `http://127.0.0.1:8099/`. This is ephemeral trusted-local .NET10/Linux/browser
execution, not a production browser direction, account/save system or Unity/Windows/
Steam delivery. Closing the owner loses this session. Do not expose it publicly.

Four parts and two coins are explicit experimental setup. Actual help at a bench costs
one part and one action turn. The owner then records persistent observed help in NPC
scope, current support in RELATION scope and a recent demonstration for that exact bench.
Its window has TTL3, an original experimental parameter, not an imported source value.
Global facts and another bench cannot stand in for these exact local facts.

Each service checks the current local conditions and an actual coin BEFORE paying its
one-turn cost, then supplies exactly one fitting from that bench. A service begun at
turn3 before expiry4 can produce its real fitting at4; an initial request at4 refuses.
The output remains acquired after expiry. No request, elapsed wall time or browser
field supplies the fitting. Reads and redraw advance no clocks.

Waiting costs one deliberately chosen action. Withdrawal costs no turn and clears only
current support/recent event, retaining actual help and output/history. Re-demonstration
requires actual past help and costs another part/turn, explicitly restoring support and
recency. Repeating it can exhaust all parts without any output; a promise cannot replace
that missing resource. No automatic refund, global reputation, blame or NPC schedule is
inferred. Refused commands pay no action/resource cost. Old intent is rejected by revision;
an uncertain/interrupted browser receipt requires explicit read, never automatic retry.

## Strict authored service conditions

The same private service now compiles a bounded typed condition before constructing
its owner. The default `independent` policy retains the existing behavior. An explicit
startup `--policy ordered` makes east service additionally require actual west delivery:
`Helped=true & Support=true & Recent=true & OtherDelivered=true`. West retains the
base expression. These are original experimental commission policies, not historical
NPC psychology, fiction, approval or a loaded dialogue catalog.

The expression observes only exact private named-bench facts. Actual help/support/recent
memory, a coin and not-already-delivered remain nonbypassable owner guards. Satisfied
condition is eligibility, not output: actual service still pays a coin and one action
before recording its one acquired fitting. Eligibility is checked before that cost;
expiry during the paid action cannot retroactively undo accepted output. An unknown
startup policy refuses rather than falling back or resetting an existing owner.

The C#8/netstandard2.1 parser consumes the whole expression, validates declared types,
parentheses and all characters, and requires all referenced facts even across an OR
branch. Missing facts cannot satisfy a negative predicate. Function bindings, source
coercion, full scoring/catalogs and Ruby/RGSS/RMXP remain unresolved. Nothing supplied
by the browser becomes a private fact or a new policy.

## Declared named-query authority

The portable Conditions library also supports declared exact `HasTag`, `HasFlag` and
`HasRecentEvent` references in a frozen named query context. All referenced scalars,
query providers/IDs and the exact context must be present before Boolean short-circuit;
unknown is incomplete, never a successful negative. It does not invoke arbitrary
functions, normalize recent-event suffixes or inherit GLOBAL/missing-subject fallbacks.
The old scalar API and independent/ordered service outcomes remain supported.

Start this same host with `--policy single-offer` for the original experimental offer
contract. Actual accepted withdrawal records `offer-closed` for that exact bench.
A paid demonstration still spends one part and one action and can renew support and
recency, but cannot reopen the closed offer. Service then refuses without coin, turn
or fitting spend/output. The independent policy deliberately remains renewable.
Closing one offer does not close its neighbor; already acquired fittings and past help
remain true. The page discloses the contract before the action and keeps closure,
current evidence and acquisition separate. This is not a moral/personality model,
approved quest canon, human social finding, account persistence or new source permission.
