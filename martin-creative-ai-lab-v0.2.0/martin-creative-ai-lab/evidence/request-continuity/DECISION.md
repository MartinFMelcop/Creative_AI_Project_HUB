# Accepted choices survive the authored scene's process

The beneficiary is the existing visible and downloadable **The coil and the shutters**
scene. Its prior in-memory Room lost the accepted conversation, guide commitment and
actual encounter when the host stopped. Refresh could only read the current process.
The new local continuity preserves that same authored experience rather than adding
another isolated study, character creator or fictional world.

Science read the complete root/workspace authorities, current process and STATE, the

the actual [Room](../../north-star/authored-scene/Host/Room.cs),

The independent Scientific recommendation preferred this continuity dependency in the
preceding selection and again for this cycle. Engineering's actual adaptation preserves
an unchanged RequestExpedition owner and replay contracts instead of declaring that the
PreparedExpedition-specific journal already covers narrative. Creative constraints keep
consent, unfinished local work and uncertain guide location visible; no new lore or moral
ranking is introduced. The primary coordinates those specialties and their ownership;
agent analyses and the protected Brain libraries are not independent human participants,
model training, author approval or a benchmark score.

Actual licensed Unity/Windows delivery remains the stronger production acceptance if a
usable Editor, activation and platform modules can be verified and executed. Appropriate
author/player/device assessment would be needed for comprehension, preference or
accessibility. Neither access nor participants are inferred from available terminal tools.

schedules, creation parsing, item/tool/unlock policy and quest/reputation catalogs require

the existing scene's actual loss of accepted choices.

## One owner and an explicit durable boundary

The [declared protocol](../../north-star/authored-scene/tools/continuity-protocol.json)
precedes new process acceptance. One authoritative actual RequestExpedition retains
Rill's offer, costs, nested Crossing, receipts and observed return. The local journal
reconstructs accepted commands, including conversation commands that change private
future permission. It does not import serialized health, delivery or return as facts.
Fixed Lure/Trail and all original gameplay rules remain the owner's decisions.

The old Recovery journal is tied to PreparedExpedition commands and embedded source
identity. Reusing its local commit-before-receipt, replay and refusal contracts is not
claiming that it already saved the narrative owner. The new format is a separate local
request journal with strict schema/kind, compiled identity and explicit incompatibility
refusal. Compiled module identity is deliberately strict: compatibility is not promised
across rebuilds, and no automatic migration or silent recovery fallback is inferred.

Durable sequence/revision counts accepted commands. Rejected feedback is transient; the
last rejected text is not falsely described as persisted. Request IDs bind accepted
command content, current-day identity is checked before duplicate handling, and an
explicit new day appends to prior history while changing the day token. Stale queued
intent and known old-day IDs cannot mutate or replay into the new day. A write that cannot
be confirmed blocks the owner until actual re-opening; it cannot become a saved receipt.

## The measurements match the claim

The actual native execution supplies43 bounded controls. The independent Python
[process instrument](../../north-star/authored-scene/tools/continuity-process.py)
supplies47 software assertions across seven actual host-process re-openings, including:

- Hear followed by actual Offer after reload, and pending terms followed by actual Confirm.
- Guide preparing before departure, with travel and delivery still unobserved.
- Actual owned-process kill during guided travel, followed by the precise next encounter beat.
- Actual delivered/observed-return state retaining three unfinished crates.
- Actual failed guided travel retaining an unaccounted Rill and reduced local-work capacity.
- Explicit new day with retained accepted history and rejected old-day intent.

These numbers describe software controls, not people, independent population observations
or effort measurements. A successful replay is not enough by snapshot equality alone:
RequestExpedition's public snapshot omits private consent/draft revisions. Therefore the
instrument executes the next actual Offer/Confirm after reload, detecting a recovery that
reproduces visible JSON while losing future permission.

Selected negative controls check accepted-request retries as saved-byte no-ops, stale
revision/day identity, client state injection and refusal to create over existing or resume
missing/corrupt data. Actual I/O uncertainty and lost receipts have their own targeted
controls under primary integration. This is not an automatic repetition of every old
Recovery fault matrix. Updated delivery and regression execution support this same new
continuity beneficiary, not extra research or portfolio units.

The [initial instrument failure](initial-instrument-failure.json) retains a real failed
primary full-verifier execution. The original assertion compared the complete continuity
receipt object on re-open. A POST receipt's reason is `Committed before receipt.`; a fresh
GET after recovery says `Current committed request run.`. Those are correctly different
operation messages. A separate actual diagnostic reproduced equal accepted text, state and
five persisted facts, with only `reason` different. The corrected assertion preserves exact
accepted text and compares `mode/run_id/revision/day/status`; semantic next-action checks
remain. Duplicate/original-revision/reason receipt metadata is verified according to its
operation rather than mislabeled saved state. No gameplay rule, fixture, timeout or storage
gate was relaxed to satisfy the instrument. The corrected process execution passed47.

## Remaining obligations

Preserve protected Brain/reference bytes, legacy variants, original media, source provenance,
notices and author authority. Local replay does not integrate full legacy NPC schedules,
reputation/factions, quest/world catalogs or narrative content. It is not approved canon,
commercial clearance, human comprehension, fairness, accessibility, enjoyment or plant/game
quality evidence. Agents cannot approve the author's world on their behalf.

Actual Linux file/process continuity is not power-loss durability, directory-fsync proof,
arbitrary-filesystem guarantees, hostile tamper resistance, account authorization or a
distributed server. Windows save behavior, Steam Cloud and licensed Unity Editor/player
execution remain distinct unexecuted production acceptances. Build/Operations stays
incomplete. Neither a passing local run nor a local commit establishes publication or CI
success; the primary verifies those separately.
