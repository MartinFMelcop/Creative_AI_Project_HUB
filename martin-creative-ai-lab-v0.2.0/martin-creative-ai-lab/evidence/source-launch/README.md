# Bounded source access, not another player package

[Execution](RUN.json) records19actual browser controls across the existing Field and
Treatment Line hosts. Both were built and launched through the same strict portfolio
entry, accepted actual owner actions, preserved state across repeated GETs and expired
normally with closed ports. `interruption.json` separately records actual SIGTERM,
exit130 and owned-process cleanup. These are overlapping software trials, not people.

`tools/test_source_launch.py` executes six refutable controls: unsupported selection,
bounded lifetime, wrong SDK, wrong owner schema, occupied port, and an actual process
advertising READY while an actual HTTP fixture serves the wrong owner JSON. The same
readiness contract rejects it. This does not establish cryptographic process/port
ownership or eliminate the reserve/release race.

The [public case study](../../showcase/README.md#launch-an-existing-source-experiment)
contains the real commands. Python3.11+ and installed SDK10.0.401 are required. The
launcher installs no SDK and never sends gameplay commands. Browser verification uses
the existing locked Playwright/Chromium setup:

```sh
python3 tools/test_source_launch.py
node showcase/launch-browser.mjs DOTNET EXTERNAL_NEW_DIRECTORY
```

The source catalog remains `showcase/portfolio.json`; code fixes the two allowed IDs
and paths as a strict contract, not a second editable registry. Existing recipient
ZIPs and C#owners remain unchanged. Build outputs can change compiled identities;
these runs are not replay of a prior frozen Host binary or Unity/Windows validation.

Initial partial-producer syntax/assertion defects and an incomplete isolated portfolio
fixture are disclosed in `initial-failures.json`. No failed execution was accepted as
a successful negative. Actual positive runs were repeated after signal/stage hardening;
only the final result is current. Baseline tool/catalog bytes are preserved separately.
No source, save, notice, package or media was retired.

This is ONE corrective repository/production-access unit after two North Star units.
Human onboarding, accessibility, speedup, ordinary-user Windows, Editor activation/
modules, Steam, commercial clearance and production acceptance remain unverified.
