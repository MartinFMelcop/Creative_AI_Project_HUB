# Server-confirmed action feedback

The remote developer window now exposes existing actions before a press: three cards
show Guardian guard or Duelist draw, paid step and counter. The server projects advice
from its actual model, and the remote accepts a bounded typed DTO. The view never loads
Combat, spends resources or admits actions. Dashed teal/amber reach rings distinguish
counter/draw range from the red pulse. Active play retains costs on unavailable actions;
suspension/disconnect replaces the cards with recovery feedback and leaves threats visible.

Advice describes an individual action at the confirmed snapshot. LIVE guard describes
timing and locked facing, not protection from every direction; ground pulses warn to
move. READY is not a reservation, prediction, combination budget or guarantee of the
next command. Normal model checks still apply, and a counter that misses still costs 12.
The projection repeats a few model thresholds deliberately; native real-model controls
must fail if their costs, timing or contact boundaries diverge. The shipped model and
PCK/Linux 0.5.0 bytes are unchanged; this is a separate developer consumer.

- 197 native controls per source/PCK delivery: 44 input, 90 transport/schema, 6 pulse
  contact and 57 action/model/presentation controls. Real costs, exact 130/340px contact
  boundaries, recovery, low resolve, guard startup/expiry, ground failure and blocked
  UI states are checked against the actual model rather than a second combat simulator.

  source/PCK. Interactive outcomes retain 5 health/3 cargo and the actual closed-server
  terminal. The authority also passes 42 live trust controls per delivery.
- 32 actual XTest source/PCK window controls cover input, costs/advice, suspension,
  held-release quarantine, outside-focus release/recovery and disconnect.
- A separate graphical source Duelist journey wins with 5 health/3 cargo. The unchanged
  native journey driver plays it; XTest F12 only captures the bolt snapshot. The agent
  inspected that image, the retained terminal, and Guardian walking/guard/suspended/closed
  frames. Cards, reach rings, ongoing world and terminal are legible at 1152x768. This
  is agent inspection and synthetic input, not human comprehension/accessibility evidence.
- Nine authority-mutant, ten TCP instrument, three result-boundary and five lease-evidence
  regressions pass. The current authority/remote contracts are the CI comparison artifacts.

Each row is one take per role using batch_400; totals include terminal grace. The
initial source run failed the existing at-most-one-clear lease gate. Its complete
observations remain in `transport-concurrent.json`; they are not replaced or relabeled
as passing. The serial repeat and PCK run pass the unchanged gate and retain actual
stale exposure, terminal matching and stream conservation. Overlap was observed, but
these takes do not isolate a cause or establish a scheduling/capacity guarantee. All
six grouped fixed policies still lose (0 health/2 cargo); no latency-playability gain is
claimed. Direct/delay_60 or the full prior matrix were not rerun here.

During development, one OS assertion incorrectly expected armored state at the initial
240px separation; the real server correctly reported range. The fixture now checks that
actual state; native controls separately cover armor. An intermediate remote run rejected
changed test-input identities and wrote no accepted evidence. The final frozen-input run
passes. Neither correction changes gameplay, admission gates or outcomes.

## Selection and limits

Compared new abilities/builds, independent observation, a larger network stack, and
production/creative alternatives. A concrete interaction limit could be delivered and
verified now without committing new class canon or an engine: existing remote actions
lacked visible readiness/cost context. ENG-022 informs predictable feedback; CRE-075 is
a contextual-HUD hypothesis, not approved class canon. SCI-017 informs real-model
controls, separated observations and preservation of the unsuccessful lease take.
No protected source/pin, license, new lab, capability state or release is changed.

The next selection should compare coherent ability/build work and actual author/player
observation against demonstrated freshness/interaction needs. Snapshot arrival gap is
still not server-state age. No local prediction, authentication, encryption, shared
world, persistence, physical controller, player benefit or production-engine claim.
