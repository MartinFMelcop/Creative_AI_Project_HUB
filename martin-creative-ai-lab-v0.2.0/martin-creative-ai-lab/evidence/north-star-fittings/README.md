# Authored equipment execution

The [record](RUN.json) binds actual source and result identities for one connected
North Star consumer. Its maturity and NS-C03/04/07 states remain unchanged.

[fittings.json](fittings.json) covers all four fittings and both approaches through
actual preparation, escort and return in source, PCK and Linux release. The independent
fresh-stage rebuild produces the same fitting observations. [The authored example](authored-example.json)
replaces one definition with a new ID, health, movement and recovery;
[its execution](authored.json) uses unchanged consumer code.

The [retained regression report](regressions.json) preserves 358 native controls and
all earlier gameplay/profile observations apart from explicit source identities.
[Workshop](workshop.json), [routes](routes.json), [return](gate.json), [look](look.json),
[dialogue](conversation.json), [appearance continuity](appearance.json),
[sound](sound.json), [mapped input](gamepad.json) and [release](results.json) bind
related current consumers. They are not independent participant studies.

[Keyboard observations](keyboard.json) record actual XTest navigation, range rejection,
make/wear, undo and fitted crossings for all three crafted pieces in source/PCK windows.
The [workshop image](workshop.png) and [crossing image](sash-crossing.png) were inspected.
The first render exposed unsupported string formatting; the fixed final consumer was
rerun. Player labels were repositioned after visual review.

Reproduce using the commands in RUN, the [consumer guide](../../north-star/prototype/README.md)
and [authoring interface](../../north-star/prototype/data/README.md). Temporary paths
in the exact executed command record can be replaced with writable task paths.
Forty-three Python regressions include malformed-type rejection and JSON tampering
with recalculated PCK/ZIP checksums. A matching checksum is integrity, not author trust.
Fixed policies, synthetic keys and agent image review establish bounded execution;
no human author productivity, balance, fun, accessibility, physical controller,
other-OS or production MMORPG validation follows.
